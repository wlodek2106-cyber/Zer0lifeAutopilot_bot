# Личный бот владельца

Это режим одного владельца (Telegram ID 428821665), а не многопользовательский
кастодиальный сервис. Telegram initData проверяется сервером; чужие аккаунты
не получают доступ к API. Штатные кнопки Deposit / Withdraw / Автопилот
работают через `wallet_runtime.py`. Старые обработчики и воркеры не запускаются.

## Без новых тестовых настроек

Нужны уже существующие TELEGRAM_TOKEN, SOLANA_PRIVATE_KEY и SOLANA_RPC_URL.
Публичный DEPOSIT_WALLET должен соответствовать приватному ключу сервера.
ADMIN_TELEGRAM_ID по умолчанию установлен на подтверждённый ID владельца.
OWNER_TEST_ENABLED и OWNER_TEST_RECIPIENT не используются, старые тестовые
эндпоинты и интерфейс удалены.

Для реальных отправок нужен Persistent Disk, смонтированный в /var/data.
Сервис проверяет именно mount, а не существование папки. Журнал подписи
должен переживать рестарты, чтобы сетевой таймаут не приводил к повторной оплате.
/health показывает wallet_configured, persistent_storage и trading_active.

## Балансы и обычные операции

- Баланс USDC / SOL берётся из mainnet RPC, не из старых виртуальных балансов.
- Deposit показывает общий личный адрес владельца для обоих активов.
  Баланс обновляется автоматически; подпись нужна только для записи в истории.
  Депозит проверяется как finalized входящий перевод без ошибки.
- Withdraw: выбор USDC или SOL, адрес, сумма, PIN. SOL не списывает USDC.
  USDC использует TransferChecked (12; decimals 6) и создание ATA при необходимости.
  Учитывается комиссия SOL и rent; весь SOL вывести нельзя.
- Идентификатор запроса и подпись сохраняются до sendTransaction.
  Повтор того же запроса возвращает старый результат; неопределённая операция
  блокирует новые отправки/сделки. Автоматического повторного платежа нет.
- COMPLETED означает finalized + err=null. SUBMITTED/UNKNOWN не являются успехом.

## Торговля

Автоторговля ВЫКЛ при каждом рестарте. Владелец включает её стандартной кнопкой,
вводит размер одной покупки в USDC и подтверждает реальные сделки. Размер
проверяется против реального баланса; уменьшение суммы не выполняется тайно.
Стратегия основного сканера сохранена: среднее до 10 наблюдений, покупка
на снижении >=0.3%, TP +3.5%, SL -2%, до 5 новых позиций, slippage 40 bps.
Это не гарантия доходности и не инвестиционная рекомендация.

Каждая новая позиция создаётся только после финализированного swap и по
фактическим изменениям балансов, а не по quote/цене экрана. P&L — фактические
USDC proceeds минус USDC cost; комиссии в SOL не конвертируются в USDC P&L.
Один swap не копируется на несколько виртуальных пользователей.
Неопределённый исход останавливает новые сделки.

«Закрыть все» останавливает торговлю и последовательно продаёт только
подтверждённые позиции нового режима, ожидая подтверждения каждой.
После рестарта массовое закрытие не возобновляется автоматически.
Старые записи trades и существующие сторонние токены не принимаются за новые
подтверждённые позиции и не продаются автоматически. История старого режима
не удаляется, но не используется для начисления фиктивных средств.

Meme Sniper остаётся выключенным: старый спекулятивный воркер не запускается.
Основной сканер торгует активами WATCHLIST, включая SOL.

## Проверка

`python3 -m unittest discover -s tests -v`

Тесты используют локальные одноразовые ключи и поддельные RPC. Реальные
переводы/сделки не выполняются. Проверка quote Jupiter (без swap/send) сама
по себе не доказывает успешную реальную сделку.
