# Тест личного вывода — 1 USDC

Это отдельный прямой перевод собственных средств владельца с серверного
кошелька. Он НЕ включает автоторговлю, обычный вывод или зачисление депозитов
и НЕ списывает виртуальный баланс пользователя. В журнале хранится отдельно
от обычных `withdrawals`.

## Настройка на Render после проверки и слияния PR

- `ADMIN_TELEGRAM_ID`: числовой Telegram ID владельца. Не username.
- `OWNER_TEST_RECIPIENT`: полный публичный адрес личного Solana-кошелька получателя.
  Не адрес USDC token account, не серверный `DEPOSIT_WALLET`.
- `OWNER_TEST_ENABLED=true`: явное включение кнопки теста.
- Существующие `TELEGRAM_TOKEN`, `SOLANA_PRIVATE_KEY` и `DEPOSIT_WALLET`
  остаются в Environment Render. Никогда не публикуйте секреты в GitHub/чате.
- Для защиты от повторной отправки требуется настоящий Persistent Disk
  с mount path `/var/data`; база приложения сохраняется на этом диске.
  Обычная папка `/var/data` без подключённого диска не подходит.

Адрес получателя и Telegram ID намеренно НЕ предзаполнены: адрес из прошлой
переписки является серверным адресом, а принадлежность Telegram ID не подтверждена.

Серверный ключ должен соответствовать `DEPOSIT_WALLET`. На его USDC ATA
нужен хотя бы 1 USDC, а на SOL-кошельке — средства на комиссию и, при необходимости,
rent создания USDC ATA получателя.

## Ручной тест

1. Открыть мини-приложение через Telegram под аккаунтом владельца.
2. Wallet → Withdraw → «Тест владельца — 1 USDC».
3. Проверить полный адрес, подтвердить действие и ввести PIN.
4. Открыть ссылку на транзакцию. `SUBMITTED`, `PREPARED` и `UNKNOWN`
   не означают успех: приложение только опрашивает статус, не отправляет повторно.
5. `COMPLETED` появляется исключительно после `finalized` и отсутствия ошибки.
   Проверить поступление 1 USDC в личном кошельке.
6. Выключить `OWNER_TEST_ENABLED` после теста.

Разрешена одна попытка на сохранённую базу, включая неопределённую или
неуспешную попытку. Подпись записывается и транзакция фиксируется в SQLite
до обращения к `sendTransaction`. Повторный POST не создаёт новый перевод,
в том числе из второго процесса. Не удаляйте таблицу/базу для «повтора»:
сначала надо установить исход предыдущей подписи в блокчейне.

Проверки перед отправкой: mainnet genesis, адрес подписанта, фиксированный
USDC mint, владельцы/состояния token accounts, баланс USDC, комиссия SOL,
идемпотентное создание ATA, TransferChecked (12; decimals 6), симуляция с
проверкой подписи. Это ограниченный инструмент разработки, не утверждение
готовности всего торгового бота к промышленной работе.

## Проверки без реальных переводов

```sh
python3 -m unittest discover -s tests -v
python3 -m py_compile main.py owner_test_withdrawal.py
```

Тесты используют новые локальные ключи и поддельный RPC. Они не требуют
секретов, не подключаются к mainnet и не отправляют реальные деньги.
